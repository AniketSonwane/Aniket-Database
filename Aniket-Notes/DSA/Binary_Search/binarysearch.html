# Binary Search

Binary Search is an efficient, logarithmic searching algorithm that operates on a sorted array. Instead of inspecting elements sequentially, it repeatedly checks the middle element (mid) and eliminates half of the remaining search space at every comparison step.

Binary Search Example:

Array: [ 10, 20, 30, 40, 50, 60, 70 ], Target = 50
Step 1: low=0, high=6 → mid=3 (arr[3]=40). 40 < 50 → Discard left half! Set low = 4
Step 2: low=4, high=6 → mid=5 (arr[5]=60). 60 > 50 → Discard right half! Set high = 4
Step 3: low=4, high=4 → mid=4 (arr[4]=50). 50 == 50 → TRUE (Match Found!)
Result: Target 50 found at index 4
Note on Duplicate Values: Standard Binary Search will return any matching index when duplicate values are present (e.g. [10, 20, 20, 20, 30] with target 20 returns index 2).

Divide and Conquer Strategy

1. Divide

Calculate middle element index: mid = low + (high - low) / 2.

2. Decide

Compare arr[mid] with target value (Equal, Less, or Greater).

3. Reduce

Discard half the array! Set low = mid + 1 or high = mid - 1.

Binary Search Step-by-Step Algorithm

1Set low = 0 and high = n - 1.
2Check condition while (low <= high).
3Calculate middle index mid = low + (high - low) / 2.
4If arr[mid] == target, return index mid.
5If arr[mid] < target, target lies in right half: set low = mid + 1.
6If arr[mid] > target, target lies in left half: set high = mid - 1.
7Repeat steps 2 to 6 until target is found or low > high.
8If loop terminates with low > high, return -1.

Complexity Analysis

Time Complexity:

Case Complexity Reason
Best Case O(1) Target is located at the first calculated mid position.
Average Case O(log n) Eliminates half of remaining search space in every iteration step.
Worst Case O(log n) Repeated halving until search space reduces to 1 or zero elements.

Space Complexity:

O(1) Constant Auxiliary Space (Iterative Implementation)

Requires only three index variables: low, mid, and high.

Algorithm Properties & Trade-offs

Requires Sorted Array

Yes (Prerequisite)
Binary Search requires elements to be pre-sorted.

Divide & Conquer

Yes
Repeatedly halves the active search domain.

Comparison-Based

Yes
Compares arr[mid] with target using == and <.

Advantages

  • Extremely fast O(log n) time complexity.
  • Halves search space at every comparison.
  • O(1) extra space in iterative implementation.

Disadvantages

  • Requires a sorted array.
  • Sorting overhead if data is unsorted.

Space Complexity

O(1) Constant Space
Only uses low, mid, high variables.
