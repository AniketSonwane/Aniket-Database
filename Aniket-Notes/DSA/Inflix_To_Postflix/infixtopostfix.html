#include <iostream>
#include <stack>
using namespace std;

int precedence(char op) {
    if (op == '^') return 3;
    if (op == '*' || op == '/' || op == '%') return 2;
    if (op == '+' || op == '-') return 1;
    return 0;
}

string infixToPostfix(string infix) {
    stack<char> s;
    string postfix = "";

    for (char ch : infix) {
        // Case 1: Operand
        if (isalnum(ch)) {
            postfix += ch;
        }
        // Case 2: Opening Parenthesis
        else if (ch == '(') {
            s.push(ch);
        }
        // Case 3: Closing Parenthesis
        else if (ch == ')') {
            while (!s.empty() && s.top() != '(') {
                postfix += s.top();
                s.pop();
            }
            s.pop(); // discard '('
        }
        // Case 4: Operator
        else {
            while (!s.empty() && precedence(s.top()) >= precedence(ch)) {
                postfix += s.top();
                s.pop();
            }
            s.push(ch);
        }
    }

    // Step 5: Pop remaining operators
    while (!s.empty()) {
        postfix += s.top();
        s.pop();
    }

    return postfix;
}

int main() {
    string infix = "A+B*C";
    cout << "Infix: " << infix << endl;
    cout << "Postfix: " << infixToPostfix(infix) << endl;
    return 0;
}

📖 Comprehensive DSA Study Notes: Infix to Postfix Conversion

1. Understanding Expression Notations

In computer science and mathematics, arithmetic expressions can be written in three distinct notations based on operator placement:

Infix Notation

Operator is placed between operands. This is the standard human-readable format, but requires parentheses and precedence rules to resolve ambiguity.

Example: A + B * C

Postfix (Reverse Polish Notation - RPN)

Operator is placed after its operands. Postfix requires zero parentheses and can be evaluated in a single linear pass using a simple LIFO stack.

Example: A B C * +

Prefix (Polish Notation)

Operator is placed before its operands. Evaluated from right to left using a stack.

Example: + A * B C

2. Why Do Compilers & Hardware Evaluate Expressions in Postfix?

When humans read A + B * C, our brain scans forward and backward to identify that * takes precedence over +. For compilers and CPUs, backtracking is inefficient.

  • No Parentheses Required: The order of operations in Postfix is unambiguous and encoded directly into the position of operators.
  • One-Pass $O(N)$ Linear Evaluation: Postfix expressions can be evaluated with a single pass using a stack without recursion or lookahead.
  • Direct Hardware Stack Mapping: Most virtual machines (such as JVM bytecode and WebAssembly) and mathematical calculators (HP-35 RPN) use stack-based evaluation.

3. Operator Precedence & Associativity Reference Table

Higher numerical priority means higher precedence. Operators with higher precedence are evaluated before lower precedence operators.

Operator Symbol Operation Name Precedence Rank Associativity Direction Handling in Stack
^ Exponentiation / Power 3 (Highest) Right to Left Pushes if top is equal (does not pop another ^ due to right-associativity)
* , / , % Multiplication, Division, Modulo 2 Left to Right Pops top if top is ^, *, /, or %
+ , - Addition, Subtraction 1 (Lowest) Left to Right Pops all operators except ( before pushing
( , ) Parentheses / Brackets 0 (Inside Stack) N/A Acts as an isolation barrier. Operators inside brackets are processed separately.

4. The 5 Golden Conversion Rules (Shunting-Yard Algorithm)

Rule 1: Operand Encountered

If the scanned character is an operand (letter A-Z or digit 0-9), directly append it to the Postfix expression.

Rule 2: Opening Bracket '('

Push '(' directly onto the Stack. It marks the boundary of a sub-expression and shields operators underneath it.

Rule 3: Closing Bracket ')'

Pop and append operators from the stack to the postfix output repeatedly until '(' is reached. Then pop and discard the '('.

Rule 4: Operator Encountered

While the stack is not empty and Precedence(Stack.top()) >= Precedence(currentOp), pop the top operator into postfix. Then push current operator.

Rule 5: End of Expression (Drain Stack)

When all characters of the infix string have been scanned, pop all remaining operators from the stack one by one into the postfix expression.

5. Time and Space Complexity Analysis

Time Complexity: $O(N)$

  • Let $N$ be the length of the infix string.
  • Each character in the infix expression is scanned exactly once ($O(N)$).
  • Every operator is pushed onto the stack at most once and popped at most once ($O(1)$ amortized per operator).
  • Total Time Complexity: $\mathcal{O}(N)$ (Linear Time).

Space Complexity: $O(N)$

  • In the worst case (e.g. nested brackets or ascending operator precedence like A+(B+(C+(D)))), the stack stores up to $N$ operators.
  • The output string stores all $N$ tokens.
  • Total Auxiliary Space Complexity: $\mathcal{O}(N)$ (Linear Space).

6. How Computers Evaluate Postfix Expressions (Evaluation Algorithm)

Once an expression is converted into postfix, the CPU or VM evaluates it using an Operand Stack:

1. Scan the postfix expression from Left to Right.
2. If an operand is encountered, push its numerical value onto the stack.
3. If an operator op is encountered:
    a. val2 = stack.pop()
    b. val1 = stack.pop()
    c. result = val1 (op) val2
    d. stack.push(result)
4. When finished, the single element remaining on the stack is the final answer!
