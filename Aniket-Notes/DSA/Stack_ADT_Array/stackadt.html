LIFO — Last In, First Out Principle

In a Stack ADT, elements are inserted and removed strictly from a single end called TOP. The last element added to the stack is always the first one to be removed.

1. Push Sequence
PUSH 10 (First In)
PUSH 20
PUSH 30
PUSH 40 (Last In)
➔
2. Stack Structure
[ 40 ] ← TOP (Last In)
[ 30 ]
[ 20 ]
[ 10 ] ← BOTTOM (First In)
➔
3. Pop Sequence
POP() returns 40 (First Out)
POP() returns 30
POP() returns 20
POP() returns 10 (Last Out)

Stack ADT Algorithms

PUSH Algorithm

  1. Check whether the stack is full (top == MAX - 1).
  2. If full, display Stack Overflow error and exit.
  3. Otherwise, increment top (top++).
  4. Store the value at arr[top] = value.
  5. Operation completed successfully.

POP Algorithm

  1. Check whether the stack is empty (top == -1).
  2. If empty, display Stack Underflow error and exit.
  3. Retrieve or remove top element.
  4. Decrement top (top--).
  5. Operation completed successfully.

PEEK Algorithm

  1. Check whether the stack is empty (top == -1).
  2. If empty, return error indicator (-1).
  3. Otherwise, return value stored at arr[top].
  4. Do not modify top or alter stack contents.

Time & Space Complexity Analysis

PUSH Operation

O(1)

Constant time addition at top index

POP Operation

O(1)

Constant time removal from top index

PEEK Operation

O(1)

Direct access to arr[top]

Space Complexity

O(N)

Linear space proportional to capacity MAX

Array Stack vs Linked List Stack

Feature Array Stack Linked List Stack
Size / Capacity Fixed capacity (pre-allocated) Dynamic (grows as needed)
PUSH Time Complexity O(1) O(1)
POP Time Complexity O(1) O(1)
Memory Allocation Contiguous memory blocks Non-contiguous dynamic nodes
Overflow Risk Possible when top == MAX - 1 Only when system memory runs out
Implementation Complexity Simple (array + index pointer) Requires node pointers & heap allocation

Real-World Applications of Stack ADT

1. Function Call Stack

Manages active function call frames, local variables, and return addresses during program execution.

2. Undo / Redo Mechanism

Text editors store editing operations on a stack to allow Ctrl+Z (Undo) and Ctrl+Y (Redo).

3. Browser Back Button

Web browsers maintain visited URLs in a stack so clicking 'Back' pops the current page and reveals the previous one.

4. Expression Evaluation

Compilers use stacks to convert Infix to Postfix/Prefix notation and evaluate arithmetic expressions.

5. Parentheses Matching

Syntax checkers use stacks to verify balanced brackets (), {}, [] in source code.

6. DFS & Backtracking

Graph Depth-First Search and backtracking algorithms (maze solving, N-Queens) rely on stacks.
