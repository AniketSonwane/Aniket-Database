💡 Easy Explanation: How Radix Sort Works

Think of Radix Sort like sorting a deck of 3-digit numbered cards! Instead of comparing numbers against each other (like asking "is 802 > 170?"), Radix Sort never compares whole numbers. Instead, it looks at one digit column at a time, from right to left!

Pass 1: Ones Place (Right)

Look only at the LAST digit. Sort into 10 buckets (0–9).

Pass 2: Tens Place (Middle)

Look only at the MIDDLE digit. Sort into 10 buckets (0–9).

Pass 3: Hundreds Place (Left)

Look only at the FIRST digit. Sort into 10 buckets (0–9). Done!

Step-by-Step Toy Example: Sort [ 170, 45, 802, 24 ]

Step 1 (ONES Digit): Look at the rightmost digit of each number.
170 → Bucket 0 | 802 → Bucket 2 | 24 → Bucket 4 | 45 → Bucket 5
Result after ONES: [ 170, 802, 24, 45 ]
Step 2 (TENS Digit): Look at the middle digit of each number.
802 → Bucket 0 | 24 → Bucket 4 | 45 → Bucket 5 | 170 → Bucket 7
Result after TENS: [ 802, 24, 45, 170 ]
Step 3 (HUNDREDS Digit): Look at the leftmost digit (pad missing digits with 0).
024 → Bucket 0 | 045 → Bucket 0 | 170 → Bucket 1 | 802 → Bucket 8
Final Sorted Array: [ 24, 45, 170, 802 ] 🎉

How Digit Extraction Works in Code

To get the single digit at place value exp (1, 10, 100...), C++ uses this simple math formula:

digit = (number / exp) % 10
Example for number 802 at TENS place (exp = 10):
1) Divide by exp: 802 / 10 = 80
2) Take modulo 10: 80 % 10 = 0
→ Current Digit = 0

Radix Sort Step-by-Step Algorithm

1Find the maximum element in the array using getMax().
2Start with place value exp = 1 (ONES digit).
3Initialize count[10] = {0} for digit frequencies (0 to 9).
4Extract the digit at position exp for each element and increment count[digit]++.
5Compute prefix cumulative sums: count[i] += count[i - 1].
6Traverse elements in reverse order and place them stably into output[count[digit] - 1].
7Copy the output[] array back into arr[].
8Multiply exp *= 10 for the next digit place value.
9Repeat steps 3–8 while maxVal / exp > 0.
10Array is completely sorted!

Complexity Analysis

Time Complexity:

Case Complexity Reason
Best Case O(d × (n + k)) Processes d digit passes, each taking O(n + k) time.
Average Case O(d × (n + k)) Determined strictly by number of digits d and radix base k=10.
Worst Case O(d × (n + k)) Non-comparison based time complexity remains linear with respect to digits and elements.

Space Complexity:

O(n + k) Auxiliary Space

Uses temporary output[100] array of size n and count[10] array of size k=10.

Algorithm Properties & Trade-offs

Non-Comparison

Yes (Non-Comparison)
Sorts numbers by grouping digits into buckets without element-to-element comparisons.

Stability

Stable (Yes)
Preserves relative order of duplicate elements via stable Counting Sort.

In-Place

Not In-Place (No)
Requires auxiliary memory for output[] and count[].

Advantages

  • Linear time O(dn) for fixed-length integer keys.
  • Faster than comparison sorts for small key lengths.
  • Stable sorting algorithm.

Disadvantages

  • Requires extra O(n + k) memory.
  • Limited to non-negative integer or fixed-format keys.

Best For

Integers / Fixed-Length Keys
Large collections of non-negative integers.
